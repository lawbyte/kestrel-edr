# Build a stealer-hunting EDR from user mode

A small team can ship a credible, production-grade infostealer EDR without a kernel driver. The condition is that v1 is designed as a **detect-fast, contain-fast correlation engine** that delegates hard blocking to enforcement Windows already provides, rather than as a user-mode imitation of CrowdStrike. Stealers change brand every few months (Lumma → Acreed → Vidar 2.0/StealC v2), but their behaviour stays put. They arrive through paste-and-run lures, read browser, wallet and messenger stores, decrypt them with DPAPI or by attacking Chrome's App-Bound Encryption, and POST a log of a few KB to a few MB to a dead-drop-resolved server within seconds to minutes. Almost every one of those steps is visible from a SYSTEM service through ETW, the DPAPI debug channel, registry telemetry and (where enabled) Sysmon. The highest-value rule is one process that touches credential stores, decrypts with DPAPI and opens an external connection within five minutes. User mode cannot synchronously stop a process from starting, opening a handle to Chrome or reading `Login Data`. The ELAM/PPL/ETW-TI path is closed to non-MVI vendors, and MVI requires a shipping commercial product with yearly lab certification. That makes the realistic route v1 user-mode, v2 depth and operations, v3 a minimal signed driver followed by an MVI application. For a self-hosted, per-company Docker deployment, the recommended stack is a Rust agent (ferrisetw, rsigma-eval, YARA-X, tonic/rustls), a Rust backend over PostgreSQL and ClickHouse, a React/shadcn console and a Tauri tray app. All of these are permissively licensed, and data never leaves the customer's premises. That design also simplifies obligations under Singapore's PDPA and Indonesia's UU PDP. It does not remove them.

## User-mode ETW sees nearly everything but blocks almost nothing

Every Windows EDR has to choose where its sensors sit. Kernel callbacks (`PsSetCreateProcessNotifyRoutineEx`, `ObRegisterCallbacks`, `CmRegisterCallbackEx`), a file-system minifilter and WFP callouts are the only **synchronous** interception points, and each requires a signed kernel image. `ObRegisterCallbacks`, for example, returns `STATUS_ACCESS_DENIED` when its routines are not in a signed image ([MS Learn](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/nf-wdm-obregistercallbacks)). Everything else is asynchronous telemetry consumed after the fact. That telemetry is better than its reputation. A SYSTEM service can consume **Microsoft-Windows-Kernel-Process** (ProcessStart/Stop, ImageLoad) ([Velociraptor](https://docs.velociraptor.app/artifact_references/pages/windows.etw.kernelprocess)) and the NT Kernel Logger's registry, file, network, handle and thread events ([Velociraptor watch_etw](https://docs.velociraptor.app/vql_reference/event/watch_etw/)). It can also consume **Microsoft-Windows-Kernel-Audit-API-Calls**, which reports `PsOpenProcess`, `PsOpenThread`, `NtSetContextThread` and `NtTerminateProcess`. Those are exactly the primitives stealers use against browsers ([Elastic Security Labs](https://www.elastic.co/security-labs/kernel-etw-best-etw)). Elastic points out that the kernel-generated ProcessStart event is harder to tamper with than Security event 4688, which passes through lsass. It also notes that Microsoft and Defender for Endpoint both prefer kernel ETW over ntdll hooks ([Elastic](https://www.elastic.co/security-labs/kernel-etw-best-etw)). Fibratus shows how far an ETW-only agent can go: it rebuilds registry paths, resolves file objects to paths, attaches token integrity and call stacks, and runs a sequence-aware rule engine on top ([Fibratus docs](https://docs.fibratus.io/telemetry/events)).

Two free signal sources close much of the driver gap. AMSI exposes de-obfuscated PowerShell, WSH, JScript/VBScript and Office VBA content to an in-process provider DLL on Windows 10 and later ([MS Learn](https://learn.microsoft.com/en-us/windows/win32/amsi/antimalware-scan-interface-portal)). Provider signature enforcement is off by default, though, so the agent must watch `HKLM\SOFTWARE\Microsoft\AMSI\Providers` and `FeatureBits` itself ([MS Learn](https://learn.microsoft.com/en-us/windows/win32/api/amsi/nn-amsi-iantimalwareprovider)). Sysmon brings a Microsoft-signed boot-start driver and a protected-process service. It emits **ProcessAccess with GrantedAccess (EID 10)**, CreateRemoteThread (EID 8), ImageLoad (EID 7), DNS (EID 22) and registry set (EID 13), the same events stealer rules are written against ([MS Learn Sysmon](https://learn.microsoft.com/en-us/sysinternals/downloads/sysmon)). Sysmon now also ships as an **optional Windows feature**, enabled with DISM and first delivered in the February 2026 KB5077241 preview ([Microsoft Support](https://support.microsoft.com/servicing/os/windows-11/2026/02/february-24-2026-kb5077241-os-builds-26200-7922-and-26100-7922-preview)). Whether it is generally available outside preview builds as of October 2026 was not confirmed. The practical design treats Sysmon as an **optional enrichment source**: if the customer enables it, the agent reads its channel and gains kernel-quality handle-access telemetry without the vendor owning a driver. Check the Sysinternals licence before bundling the standalone binary.

| Capability | User-mode service (v1) | Signed driver | AM-PPL + ETW-TI |
|---|---|---|---|
| Process start/stop, image load | Yes, async (Kernel-Process ETW) | Yes, can veto creation | — |
| File open/read of credential stores | Yes, async (Kernel-File ETW; or SACL 4663) | Yes, minifilter can deny | — |
| Handle opened to chrome.exe | Partial (Audit-API-Calls; Sysmon EID 10 if present) | Yes, can strip rights | — |
| Remote write/APC/SetThreadContext into browser | Partial (Audit-API-Calls SetContextThread; Sysmon EID 8) | Partial | Yes (kernel-generated) |
| Network connect / DNS | Yes (Kernel-Network, DNS-Client) | Yes, WFP callout can veto | — |
| Block network for a process or host | Yes, via user-mode WFP filters | Stronger (terminating callouts) | — |
| Protect agent from admin kill | No (raise the bar only) | Handle stripping | Yes (PPL) |

The privileged tier is out of reach for now. ETW-TI (`{F4E1897C-BB5D-5668-F1D8-040F4D8DD344}`) supplies kernel-generated events for executable allocations, remote APCs, SetThreadContext and remote VM read/write. The kernel serves it only to Antimalware-PPL consumers ([Origin HQ](https://www.originhq.com/research/securitytrace-etw-ppl)). Launching a service as AM-PPL requires an installed ELAM driver that carries the vendor's certificate hash, and every non-Windows DLL the service loads must be signed with that same certificate ([MS Learn](https://learn.microsoft.com/en-us/windows/win32/services/protecting-anti-malware-services-)). An ELAM driver must be WHQL-signed, and **"the submission fails if the vendor is not an MVI member"** ([MS Learn](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/elam-prerequisites)). MVI in turn requires a commercially available real-time anti-malware product, use of Trusted Signing, an NDA and programme licence, and certification within the last 12 months from an accepted lab, such as AV-Comparatives Approved, AV-Test 97% Real-World or SE Labs AAA ([MS Learn MVI criteria](https://learn.microsoft.com/en-us/unified-secops-platform/virus-initiative-criteria)). A January 2026 finding showed that AutoLogger sessions can consume ETW-TI without PPL. MSRC declined to treat this as a vulnerability because admin-to-PPL is not an enforceable boundary ([Origin HQ](https://www.originhq.com/research/securitytrace-etw-ppl)). The trick is undocumented and could disappear at any time, so a product must not depend on it.

The kernel itself is also moving. Starting with the April 2026 update, Windows 11 24H2/25H2/26H1 and Server 2025 remove trust for drivers signed under the legacy cross-signing programme. New kernel code must be **WHCP-certified and signed through the Hardware Dev Center** ([The Register](https://www.theregister.com/2026/03/27/microsoft_kernel_trust/)), and HDC submissions need an EV certificate registered to the Partner Center account ([MS Learn](https://learn.microsoft.com/en-us/windows-hardware/drivers/dashboard/code-signing-reqs)). After the CrowdStrike outage, Microsoft's Windows Resiliency Initiative privately previewed a user-mode "Windows endpoint security platform" with eight large MVI partners in July 2025 and added MVI 3.0 requirements for ring-based deployment ([Windows Experience Blog](https://blogs.windows.com/windowsexperience/2025/06/26/the-windows-resiliency-initiative-building-resilience-for-a-future-ready-enterprise)). As of March 2026 there was **no public timeline** for those APIs. Pavel Yosifovich summarised the limitation that shapes v1: in user mode, "you learn about a process only after it starts" ([Cybersecurity Dive](https://www.cybersecuritydive.com/news/microsoft-windows-resilience-initiative-security-kernel/813416/)). The platform is NDA-only and should be treated as unavailable for planning.

Performance is mainly an ETW-plumbing problem. Real-time sessions should start with MinimumBuffers equal to MaximumBuffers, a BufferSize of 64 KB or less, and a FlushTimer of 5-10 seconds. The agent should poll `EventsLost` and `RealTimeBuffersLost` through `ControlTrace(EVENT_TRACE_CONTROL_QUERY)` ([MS Learn](https://learn.microsoft.com/en-us/windows/win32/api/evntrace/ns-evntrace-event_trace_properties)). The consumer callback should only copy each event into a queue: in krabsetw, a throwing callback kills the trace ([krabsetw](https://github.com/microsoft/krabsetw)). Volume control can follow Elastic. Elastic Defend explicitly is "not designed to provide a complete capture of all system events". It deduplicates and aggregates file events, and evaluates its most verbose API events on the host without streaming them ([Elastic Defend](https://www.elastic.co/guide/en/security/8.19/endpoint-event-capture.html), [Elastic Labs](https://www.elastic.co/security-labs/doubling-down-etw-callstacks)). For a stealer-focused product this is good news. The data that matters, which is opens of roughly 60 credential paths, DPAPI calls, browser handle access, LOLBin launches and outbound connections, can be filtered tightly at the source.

## Stealers rotate brands quarterly, but four behaviours never change

The market numbers explain why detection must be family-agnostic. Flashpoint counts **11.1 million machines infected by infostealers in 2025 and 3.3 billion stolen credentials, cookies and tokens**. Its 2025 ranking is Lumma, Acreed, Rhadamanthys, Vidar, StealC, with Vidar 2.0 the most-used stealer by January 2026 ([Help Net Security](https://www.helpnetsecurity.com/2026/03/12/agentic-attack-chains-infostealers-criminal-markets/)). The May 2025 takedown seized about 2,300 Lumma domains after Microsoft counted 394,000 infected PCs in two months ([Microsoft](https://www.microsoft.com/en-us/security/blog/2025/05/21/lumma-stealer-breaking-down-the-delivery-techniques-and-capabilities-of-a-prolific-infostealer/)). Lumma's infrastructure was rebuilt within weeks ([Trend Micro](https://www.trendmicro.com/en/research/25/g/lumma-stealer-returns.html)), and Operation Endgame dismantled Rhadamanthys in November 2025 ([Help Net Security](https://www.helpnetsecurity.com/2025/11/13/rhadamanthys-infostealer-operation-disrupted/)). Since then Vidar has led Russian Market log sales, and Lumma persists mainly in ClickFix campaigns ([Intrinsec](https://www.intrinsec.com/wp-content/uploads/2026/04/TLP_CLEAR-20260424-New_Vidar.pdf)). Each vendor measures share differently: log uploads, infected hosts or detections. Rules keyed to a family name therefore age in months. Rules keyed to behaviour survive.

### Delivery: paste-and-run lures and user-writable folders

Paste-and-run social engineering is the dominant 2025-2026 entry point. ESET recorded a **108% rise in ClickFix detections from H2 2025 to H1 2026** ([ESET](https://www.eset.com/int/business/threat-report/)). The lure has spread from the Run dialog to the Explorer address bar and file-upload dialogs (FileFix), to Windows Terminal opened with Win+X (seen with Lumma in February 2026), and to nslookup staging where the DNS response's `Name:` field is executed ([The Hacker News](https://thehackernews.com/2026/03/microsoft-reveals-clickfix-campaign.html), [Security Affairs](https://securityaffairs.com/188039/hacking/microsoft-alerts-on-dns-based-clickfix-variant-delivering-malware-via-nslookup.html)). Each surface leaves its own artefact. Run-dialog executions write the pasted string to `RunMRU`, and the key is written only if execution succeeds ([Microsoft](https://www.microsoft.com/en-us/security/blog/2025/08/21/think-before-you-clickfix-analyzing-the-clickfix-social-engineering-technique/)). Address-bar FileFix writes `TypedPaths` ([Elastic rule](https://detection.fyi/elastic/detection-rules/windows/execution_windows_filefix_typedpaths/)). Browser-dialog FileFix produces a browser parent spawning a shell whose command line contains `#` ([SigmaHQ 4be03877](https://detection.fyi/sigmahq/sigma/windows/process_creation/proc_creation_win_filefix_browsers)). The "command # I am not a robot" comment trick gives a high-signal process rule: explorer parent, `#` in the command line, and a lure keyword ([SigmaHQ d487ed4a](https://detection.fyi/sigmahq/sigma/windows/process_creation/proc_creation_win_susp_clickfix_filefix_execution/)). Kaspersky's analysis of 5 million 2025 stealer logs adds two location priors. **About 35% of infections started from files run in `%LOCALAPPDATA%\Temp`**, and **about 32% came from `C:\Windows\Microsoft.NET\Framework`**, meaning hollowing into MSBuild/RegAsm-type binaries ([Kaspersky via SocialNews](https://www.socialnews.xyz/2026/06/17/kaspersky-35-of-infostealer-infections-begin-with-users-running-files-directly-from-temporary-folders/)). Cheap static tells round this out. Unit 42 documented Vidar/Lumma loaders null-padded to **491 MB** to defeat scanners, self-signed impersonation certificates, and a Defender binary sideloading a malicious `MpClient.dll` ([Unit 42](https://unit42.paloaltonetworks.com/vidar-stealer-xmrig-miner-campaign-analysis/)).

### Collection and decryption: credential stores, DPAPI and App-Bound Encryption

Every major family collects the same core set. That set is Chromium `Login Data`, `Network\Cookies`, `Web Data` and `Local State`; Firefox `key4.db`, `logins.json` and `cookies.sqlite`; wallet-extension LevelDB folders; Discord, Telegram `tdata`, Steam `ssfn`, FileZilla and WinSCP; VPN profiles; and increasingly `.aws`, `.azure` and MSAL token caches ([Trend Micro on Vidar 2.0](https://www.trendmicro.com/en/research/25/j/how-vidar-stealer-2-upgrades-infostealer-capabilities.html), [Microsoft on Lumma](https://www.microsoft.com/en-us/security/blog/2025/05/21/lumma-stealer-breaking-down-the-delivery-techniques-and-capabilities-of-a-prolific-infostealer/)). SigmaHQ's 2025 path rule enumerates about 50 browser vendor folders ([SigmaHQ a1dfd976](https://detection.fyi/sigmahq/sigma/windows/file/file_access/file_access_win_susp_process_access_browser_cred_files/)). Its narrower "uncommon application" rule explicitly **requires the Kernel-File ETW provider** and warns that it "requires heavy baselining" ([SigmaHQ 91cb43db](https://detection.fyi/sigmahq/sigma/windows/file/file_access/file_access_win_browser_credential_access/)). Elastic's smash-and-grab pattern, a process start followed by three or more distinct sensitive files within one minute, cuts most of that noise ([Elastic](https://www.elastic.co/security-labs/detect-credential-access)). Decryption leaves a separate trail. With the `Microsoft-Windows-Crypto-DPAPI/Debug` channel enabled, event **16385** records `SPCryptUnprotect` with a DataDescription such as "Google Chrome" and the caller's PID. Any caller other than the browser or `elevation_service.exe` is suspicious ([Google Security Blog](https://security.googleblog.com/2024/04/detecting-browser-data-theft-using.html)).

Chrome's App-Bound Encryption pushed stealers toward noisier techniques without stopping them. The first bypass appeared **under 45 days after release** ([SpyCloud](https://spycloud.com/blog/infostealers-bypass-new-chrome-security-feature/)). ABE's elevation service validates only the caller's path, so code inside the browser or its application directory can still decrypt ([SpecterOps](https://specterops.io/blog/2025/08/27/dough-no-revisiting-cookie-theft/)). Six bypass classes now circulate, and each has a telemetry handle a user-mode agent can catch.

The first class abuses remote debugging and CDP. Chrome 136 restricts it on the default profile, so attackers now pair `--remote-debugging-*` with an alternate `--user-data-dir`, `--headless` or off-screen windows ([Chrome Developers](https://developer.chrome.com/blog/remote-debugging-port), [SigmaHQ 3e8207c5](https://detection.fyi/sigmahq/sigma/windows/process_creation/proc_creation_win_browsers_chromium_headless_debugging/), [Elastic](https://www.elastic.co/docs/reference/security/prebuilt-rules/rules/windows/credential_access_browsers_unusual_parent)). The second calls the elevation service's COM interface directly: Elastic saw processes kill chrome.exe several times and then start `elevation_service.exe` within one second. The third injects into chrome.exe; Lumma used QueueUserAPC in February 2026. The fourth reads CookieMonster out of process memory ([Elastic](https://www.elastic.co/security-labs/katz-and-mouse-game)). The fifth enables CDP inside a running browser through injection (August 2026), which shows up as Sysmon EID 8 into chrome or msedge plus EID 10 with GrantedAccess `0x143a` ([SpecterOps 2026](https://specterops.io/blog/2026/08/13/chrome-devtools-protocol-cookie-theft/)). The sixth, from **VoidStealer v2.0 (March 2026)**, attaches as a debugger and sets hardware breakpoints on browser threads to catch the `v20_master_key` in plaintext, needing neither injection nor admin rights ([Gen Digital](https://www.gendigital.com/blog/insights/research/voidstealer-abe-bypass)). All six techniques act on a browser process from outside it, so a stealer agent must monitor **who opens, writes to, debugs or sets thread context on browser processes**, not just who reads browser files.

### Exfiltration: small payloads, fast uploads, dead-drop C2

Exfiltration is fast, small and routed through legitimate services. Lumma checks Telegram first and Steam profiles as fallbacks to find its C2, then uploads in chunks over HTTPS POST ([Microsoft](https://www.microsoft.com/en-us/security/blog/2025/05/21/lumma-stealer-breaking-down-the-delivery-techniques-and-capabilities-of-a-prolific-infostealer/)). Vidar 2.0 uses Telegram and Steam dead drops and multipart uploads, and runs multithreaded specifically to shorten its time on the host ([Trend Micro](https://www.trendmicro.com/en/research/25/j/how-vidar-stealer-2-upgrades-infostealer-capabilities.html)). Acreed resolves C2 through a **BNB Smart Chain `eth_call` on port 8545**, uses distinctive user agents, and produces logs of just a few KB, compared with Lumma's 1-5 MB ([Intrinsec](https://www.intrinsec.com/wp-content/uploads/2025/09/TLP-CLEAR-Sept-2025-Acreed-infostealer-EN.pdf)). StealC v2 posts RC4-wrapped JSON to `.php` endpoints and can self-delete on command ([Zscaler](https://www.zscaler.com/blogs/security-research/i-stealc-you-tracking-rapid-changes-stealc)). Non-browser access to `api.telegram.org` is already a SigmaHQ rule ([SigmaHQ c3dbbc9f](https://detection.fyi/sigmahq/sigma/windows/network_connection/net_connection_win_domain_telegram_api_non_browser_access)). Red Canary advises blocking blockchain RPC endpoints wherever they are not needed ([Red Canary via Zscaler](https://www.zscaler.com/blogs/cybersecurity-best-practices/intelligence-insights-august-2026)). No source gave a median execution-to-exfiltration time. The design should therefore assume seconds, and treat any response that waits on a human as recovery, not prevention.

Prevention outside the agent is uneven. Credential Guard explicitly does **not** protect website passwords ([MS Learn](https://learn.microsoft.com/en-us/windows/security/identity-protection/credential-guard/credential-guard-considerations)). Device Bound Session Credentials became generally available in Chrome on Windows in 2026 ([Google Workspace Updates](https://workspaceupdates.googleblog.com/2026/05/prevent-account-takeovers-with-DBSC-now-generally-available-in-the-Chrome-browser-for-Windows.html)). DBSC needs a TPM and site support, and in-browser CDP lets an attacker ride the live bound session anyway ([Constella](https://constella.ai/blog/google-just-fixed-session-cookie-theft-in-chrome-here-is-what-it-still-cannot-stop/), [SpecterOps](https://specterops.io/blog/2026/08/13/chrome-devtools-protocol-cookie-theft/)). What does block stealers are execution controls. Microsoft lists ASR prevalence and obfuscation rules, App Control/AppLocker against mshta, removing the Run dialog by policy, a Windows Terminal paste warning and script-block logging ([Microsoft ASR reference](https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference), [Microsoft ClickFix guidance](https://www.microsoft.com/en-us/security/blog/2025/08/21/think-before-you-clickfix-analyzing-the-clickfix-social-engineering-technique/)). The agent cannot enforce those controls itself in v1, but it can **deploy and verify them**, so the OS kernel does the blocking.

## Employers expect Defender P1 parity before they value depth

Buyers measure a new EDR against the cheapest incumbent bundle. Gartner's EPP baseline requires malware and fileless prevention, attack-surface reduction such as device control and host firewall, and behavioural detection and blocking ([Gartner via Spotlight AR](https://research.oz.spotlightar.com/reports/magic-quadrant-endpoint-protection-platforms-2025/market-definition)). CrowdStrike's entry tier, Falcon Go at **$59.99/device/year**, already includes device control and firewall management ([CrowdStrike pricing](https://www.crowdstrike.com/en-us/pricing/)). MDE P1 covers isolation, stop-and-quarantine and file indicators ([MS Learn](https://learn.microsoft.com/en-us/defender-endpoint/respond-machine-alerts)). The upsell everywhere is searchable telemetry and live response: MDE P2 versus P1, SentinelOne Complete versus Control ([MS Learn MDB](https://learn.microsoft.com/defender-business/mdb-overview), [SentinelOne pricing](https://www.sentinelone.com/pricing)). Mid-market buyers reward simplicity over depth. Huntress tops G2's small-business EDR grid with Ease of Admin **9.6 against a category average of 8.8** by combining a light agent, plain-language incident reports and approve-to-run remediation ([G2](https://g2.com/categories/endpoint-detection-response-edr/small-business)). The opportunity for a stealer-focused product is a narrow detection scope done with high fidelity, plus a clean operator experience. It can coexist with Microsoft Defender as the AV, as Huntress and Sophos MDR do, instead of competing with it.

## A permissive Rust stack covers nearly every component

The language decision (Rust) is well supported. **ferrisetw** provides safe Rust ETW consumption ported from krabsetw under MIT/Apache-2.0. Its last release, 1.2.0, was in June 2024, so the team should plan to fork it or drop to `windows-rs` ([crates.io](https://crates.io/api/v1/crates/ferrisetw)). **rsigma-eval** (MIT) compiles Sigma once, supports all eight correlation types and pySigma-style pipelines, and evaluates one event against 1,000 rules in about 30 µs ([docs.rs](https://docs.rs/crate/rsigma-eval/0.22.0)). **YARA-X** (BSD-3, 1.21.0) is 5-10× faster than YARA on regex-heavy rules ([VirusTotal](https://blog.virustotal.com/2025/06/)), but it does **not implement process scanning** ([YARA-X docs](https://virustotal.github.io/yara-x/docs/intro/yara-x-vs-yara/)). Memory scanning therefore means reading regions with ReadProcessMemory and scanning the buffers. Mullvad's `windows-service` handles the SCM, and **tonic** provides bidirectional gRPC over rustls ([windows-service-rs](https://github.com/mullvad/windows-service-rs), [tonic](https://github.com/hyperium/tonic)). Rustinel (Apache-2.0) already combines ETW, Sigma, YARA and IOCs in Rust. Its README states it has no anti-tamper, no pre-execution blocking and no console, which is a fair description of what this project must add on top ([Rustinel](https://github.com/karib0u/rustinel)).

The licence traps are specific. Velociraptor is AGPL-3.0 ([LICENSE](https://raw.githubusercontent.com/Velocidex/velociraptor/master/LICENSE)). Wazuh is GPLv2 with an AGPLv3 engine ([Wazuh](https://github.com/wazuh/wazuh)). golang-etw and RedEdr are GPL-3.0. OpenEDR is source-available, not open source ([OpenEDR LICENSE](https://github.com/ComodoSecurity/openedr/blob/main/LICENSE.md)). Elastic's detection rules are ELv2, which forbids providing them "as a hosted or managed service" ([Elastic License](https://www.elastic.co/licensing/elastic-license)). That matters if this ever becomes an MSSP offering. Use these projects as design references only, and enforce a GPL/AGPL/ELv2/SSPL deny-list in CI with `cargo-deny`.

Signing is cheaper than the team might expect, provided the right entity holds the certificate. **Azure Artifact Signing** (formerly Trusted Signing) went GA in January 2026 at **$9.99/month for 5,000 signatures** ([DevClass](https://devclass.com/2026/01/14/code-signing-windows-apps-may-be-easier-and-more-secure-with-new-azure-artifact-service/)). Organisations in Singapore are eligible, individual developers only in the US and Canada, and Indonesia is not on the list ([MS Learn](https://learn.microsoft.com/en-us/azure/artifact-signing/quickstart)). A Singapore-registered company can therefore sign the agent, the tray app and the MSI from GitHub Actions. An Indonesian-only entity would need a conventional OV/EV certificate on an HSM. Artifact Signing issues no EV certificates, so the v3 driver needs a separate EV certificate plus HDC attestation or WHCP. For builds, cargo-xwin cross-compiles the agent from Linux and runs tests under Wine ([cargo-xwin](https://pypi.org/project/cargo-xwin/0.14.8)). WiX MSIs, Tauri MSIs, real ETW integration tests and signing belong on `windows-2025` GitHub runners ([actions/runner-images](https://github.com/actions/runner-images)).

## Queue, drawer, page: UI patterns that cut analyst toil

Leading consoles converge on one backbone. Detect/Respond, Investigate/Hunt, Assets and Configure sit in a left nav. Every list follows the same **queue → side drawer → full page** pattern, and response buttons stay pinned in an action bar on incident and device pages. Defender's incident queue adds bookmarkable filter sets, a 0-100 priority score whose contributing factors appear in the side panel, and arrow-key stepping through incidents without closing the drawer ([MS Learn](https://learn.microsoft.com/en-us/defender-xdr/incident-queue)). Elastic adds grouping by up to three nested fields with group-level bulk actions ([Elastic](https://www.elastic.co/guide/en/security/8.19/alerts-ui-manage.html)). Defender's device page puts Isolate, Collect package, Live response and Scan in a top action bar. Its "Effective settings" tab shows each setting's value and source, which answers "why is this on?" without opening the policy editor ([MS Learn](https://learn.microsoft.com/en-us/defender-endpoint/device-timeline-event-flag)). Huntress structures remediation as "what we already did / approve-to-run / manual steps", and releases isolation only when the checklist is complete, recording who released it and when ([Thread runbook](https://docs.getthread.com/skill-library/vendor-runbooks/huntress-edr-incident)). That structure suits the IT generalists who will run a self-hosted SMB deployment.

The complaints are as instructive as the praise. Reviewers fault CrowdStrike for clutter and hard-to-remember side menus ([PeerSpot](https://www.peerspot.com/questions/what-needs-improvement-with-crowdstrike-falcon)). They fault SentinelOne for laggy large queries and for having to "build new exclusions daily" ([PeerSpot](https://www.peerspot.com/products/sentinelone-singularity-complete-pros-and-cons)). Microsoft ran a 2025 programme specifically to fix Defender portal latency ([MC1042925](https://mc.merill.net/message/MC1042925)). For visualisation, the proven idiom is Elastic's top-down process tree: elapsed time between parent and child, count pills for file, registry and network events, and a detail panel per node ([Elastic analyzer](https://docs-v3-preview.elastic.dev/elastic/docs-builder/docs/3875/solutions/security/investigate/visual-event-analyzer.md)). Elastic's "verbose mode off by default" convention hides noise and surfaces user-driven activity ([Elastic Session View](https://www.elastic.co/docs/solutions/security/investigate/session-view)). Accessibility guidance is consistent across sources: never encode severity by colour alone, keep the palette small, and define keyboard focus order early ([Grafana](https://grafana.com/blog/3-tips-to-improve-your-grafana-dashboard-design/?pg=blog), [Fuselab](https://fuselabcreative.com/industries/cybersecurity-ux-design)).

For a stealer product, the incident page should open with a **plain-language storyline**, for example: "`setup_x64.exe` from Downloads read Chrome passwords, decrypted them with DPAPI and uploaded 2.1 MB to an IP resolved via Telegram 14 s later; the agent killed it and blocked the destination." Below that come a compact process tree with signer and reputation badges, a **"data at risk" panel** listing which credential categories were touched (browser passwords, cookies, wallets, Discord, cloud tokens), and a remediation checklist. The checklist goes beyond the endpoint, because stolen sessions survive a password reset. Post-infection guidance from SpyCloud and others is to revoke sessions and tokens, not only to reset passwords ([SpyCloud](https://spycloud.com/blog/infostealers-bypass-new-chrome-security-feature/)). The console should list "Revoke M365/Google sessions for user X" as a manual step in v1 and automate it in v2.

The employee app should stay small. CrowdStrike added only a status tray icon in October 2024 (running, not running, error) ([U-M ITS](https://michigan.it.umich.edu/news/2024/10/25/new-crowdstrike-falcon-sensor-status-icon-for-windows)). Its users request exceptions through help-desk tickets with screenshots ([UAH KB](https://uah.teamdynamix.com/TDClient/2075/Portal/KB/PrintArticle?ID=137260)), which leaves room for a better flow. Sophos shows status, detections and events, keeps settings behind the tamper password, and allows a four-hour admin override that auto-reverts ([Sophos agent docs](https://docs.taegis.secureworks.com/sophos_agent/sophos_agent_app_ui/sophos_endpoint_ui/)). Microsoft lets admins brand notifications with IT contact details, and critical detections cannot be suppressed even when other notifications are ([MS Learn](https://learn.microsoft.com/en-us/defender-endpoint/configure-notifications-microsoft-defender-antivirus)). The recommended Tauri tray app has four parts. **Status** shows a shield state with a text label (Protected / Attention / Isolated / Not running), last policy sync and a Quick check button. **Activity** shows blocked-item cards written in plain language. **Request review** pre-fills hostname, file, hash and detection, collects a justification and opens a console ticket. **Help and privacy** shows the company's IT contact and the monitoring notice. Restore and allow actions remain admin-only. The tray process runs as the user with no privileges and talks to the SYSTEM service over an ACL-restricted named pipe with a rotating token, as Fleet Desktop does ([Fleet](https://fleetdm.com/guides/fleetd-authentication)).

Several design choices follow from the evidence above. The **detection engine runs on the endpoint**, because exfiltration happens in seconds and a server round-trip wastes the response window. The server re-runs correlations across hosts and stores telemetry for investigation. The agent keeps a **process table keyed by a stable process GUID** (boot ID + PID + start time), because PIDs are reused and the DPAPI-to-process join depends on it ([Google](https://security.googleblog.com/2024/04/detecting-browser-data-theft-using.html)). Prevention in v1 has three parts. Containment is fast, through suspend, kill and WFP block. OS-native enforcement is deployed and verified by the agent. Canaries give near-zero-false-positive tripwires.

The **hardening pack** is what makes "prevent" honest without a driver. It writes and verifies the controls Microsoft recommends against stealers and ClickFix: App Control/AppLocker rules blocking `mshta.exe` and execution from `%TEMP%`, the Run-dialog removal policy, the Windows Terminal multi-line paste warning, PowerShell script-block logging, and ASR rules (prevalence/age `01443614-…`, obfuscated scripts `5beb7efe-…`, impersonated system tools `c0033c00-…`) wherever Defender is the active AV ([MS Learn ASR](https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference), [Microsoft](https://www.microsoft.com/en-us/security/blog/2025/08/21/think-before-you-clickfix-analyzing-the-clickfix-social-engineering-technique/)). It also enables the Crypto-DPAPI/Debug channel the detections depend on. Each control has an Audit stage and an Enforce stage in policy, and the console shows effective state per device.

Network blocking uses **user-mode WFP filters**, as Fibratus's `isolate` action does ([Fibratus](https://docs.fibratus.io/rules/actions/isolate)). The agent's provider and sublayer use maximum weight and hard-permit rules for the agent's own server, and it audits WFP Security events 5446-5450 to catch EDRSilencer-style filters that silence agents ([SCRT](https://blog.scrt.ch/2025/08/25/blinding-edrs-a-deep-dive-into-wfp-manipulation/)). WFP matches IPs, not domains. Domain policy, such as "no non-browser process may reach `api.telegram.org`, `steamcommunity.com` profiles, Discord webhooks or `*:8545`", is implemented by mapping DNS-Client answers to IPs and adding short-lived per-application block filters. This is a design inference that needs lab validation.

### Phases

**v1, "Stealer Shield" (MVP).** The agent includes the full sensor set above, the process table, rsigma-eval with a sequence engine, YARA-X on new user-path executables, the ST and TP rules, suspend/kill/quarantine, user-mode WFP isolation and destination blocking, the hardening pack, canaries and a SQLite outbox. Updates use a signed Ed25519 manifest, the agent is installed from a signed MSI with an enrolment token, and an uninstall token is required for removal. The service DACL denies stop and config changes to Administrators, there is a watchdog, and heartbeats carry sequence numbers and ETW-loss counters. On the server side, v1 delivers enrolment, policies with Audit and Protect modes, endpoint inventory with health and effective settings, an alerts queue grouped into incidents, the incident storyline with process tree and data-at-risk panel, response actions with an action log, IOCs, exclusions created from alerts with a scope preview, three roles (Admin, Analyst, Read-only) with OIDC, a hash-chained audit log, a syslog/webhook SIEM feed and email/Slack/Teams notifications. The tray app delivers status, activity, review requests, IT contact and the privacy notice. v1 explicitly excludes NGAV (rely on Defender), device control, a hunting UI, live response and any driver. It also leaves out keystroke and screenshot capture, deliberately and for good. At a rough planning estimate, this is two to three engineers for about two quarters. Most of the risk sits in ETW enrichment and false-positive tuning, not in the UI.

**v2, "Detect & Respond" (Standard).** v2 adds a telemetry hunting UI (Sigma and SQL over ClickHouse, saved and scheduled queries, custom rules), and live response with a signed script library, per-action RBAC and full command logging on the MDE model. It also adds device control for USB storage, which MAS TRM 11.1.4 expects, plus software inventory with CVE matching and investigation-package collection. Memory scanning arrives here: YARA-X over regions read from browser processes after ST-07 hits. Identity integrations automate session revocation in Entra ID and Google Workspace when cookies or tokens were at risk. v2 also brings ring-based rollout of agent and rule updates (MVI 3.0 expects deployment rings anyway), scheduled PDF and executive reports, a NATS-backed scale-out profile, and an MSP multi-tenant mode.

**v3, "Kernel & Certification" (Advanced).** v3 adds a minimal WHCP/HDC-signed driver whose only job is to veto and forward. It uses `ObRegisterCallbacks` to strip VM_READ, VM_WRITE and CREATE_THREAD from untrusted handles to browsers and to the agent, a minifilter pre-create deny on credential stores for untrusted images, and process-creation veto for ST-12. All parsing stays in user mode, in line with Microsoft's direction. The next steps are an independent lab certification, then an MVI application, then an ELAM driver and AM-PPL service for ETW-TI and true self-protection. Further v3 candidates are static ML (EMBER2024-based) ([arXiv](https://arxiv.org/abs/2506.05074v1)), VSS rollback, automated remediation playbooks and an optional managed-SOC wrapper.

### Key risks and limitations

The hard limit of v1 is that **user mode cannot synchronously stop** a process from starting, opening a browser handle or reading a credential file. A fast multithreaded stealer can finish collection, and possibly upload a few KB, before an asynchronous kill lands. Suspend-on-suspicion, WFP destination blocking and OS-native controls shrink that window but do not close it. The console must therefore present every ST-04 hit as a probable credential compromise and drive session revocation, never as "threat blocked, nothing to do".

Tamper resistance is bounded by the same constraint. Microsoft treats admin-to-PPL as non-enforceable ([Origin HQ](https://www.originhq.com/research/securitytrace-etw-ppl)), so an attacker with admin rights can stop ETW sessions, take ownership of the service, add WFP filters or toggle AMSI. Without PPL, v1 can only make tampering loud: heartbeat gaps and event-rate collapse are the real control. ETW drops events under load, and no benchmark of Kernel-File ETW cost was found, so file-access coverage must be load-tested on low-end hardware. G2 reviewers already penalise heavy agents on older machines ([G2](https://g2.com/categories/endpoint-detection-response-edr/small-business)). Dependency risk centres on ferrisetw's stale upstream and on native Sysmon's unconfirmed GA status.

The money and time costs sit mostly in v3. Artifact Signing costs about $10/month for a Singapore entity. Kernel work needs an EV certificate, an HDC account and HLK testing. MVI needs a commercial product with a yearly lab certification, which means ELAM and ETW-TI are realistically 18 months or more away. That timeline is a judgment, not a sourced figure. Licence hygiene requires DRL 1.1 author attribution in the alert UI, no Elastic rules, and the WiX maintenance fee once revenue passes $10k.

Privacy is an obligation, not an afterthought. Under Singapore's PDPA, collection reasonable for managing employment, explicitly including monitoring use of company IT resources, does not need consent, but employees must be notified ([Baker McKenzie](https://resourcehub.bakermckenzie.com/en/resources/global-data-and-cyber-handbook/asia-pacific/singapore/topics/data-processing-in-the-employment-context)). Relying on legitimate interests requires a documented assessment. Breaches of significant scale (indicatively 500 or more individuals) must be notified, and fines reach **10% of Singapore turnover or S$1 million** ([PwC](https://www.pwc.com/sg/en/personal-data-protection/assets/pdpa-updates-202011.pdf)). Indonesia's UU PDP requires a **DPIA for systematic monitoring**, a DPO for large-scale monitoring, **72-hour breach notification**, and adequacy, safeguards or consent for cross-border transfers, with criminal fines of IDR 4-6 billion ([Norton Rose Fulbright](https://www.nortonrosefulbright.com/en-il/knowledge/publications/31bce8f0/highlights-of-indonesias-personal-data-protection-law)). Self-hosting avoids the transfer question only if the vendor never pulls telemetry for support. The product therefore needs these from v1: a tray-visible monitoring notice; per-type retention; minimisation switches (no command lines for chosen paths, hashed usernames, no file-content upload); audit of analyst access to employee data; per-user export and deletion; and a shipped DPIA template. Collecting file *paths* that reveal personal documents, or capturing URLs, should be off by default.

## Conclusion

The research changes the framing of the build. The question for v1 is not "kernel or user mode" but **which point in the stealer chain each mechanism owns**. The OS kernel owns execution policy, through App Control, ASR and Run-dialog removal, if the agent deploys and verifies it. User-mode ETW owns fast behavioural correlation, especially the read → decrypt → send sequence, which no stealer family can avoid. WFP owns the exit. A narrow product that does those three things well, and tells an IT generalist in one sentence what was stolen and which sessions to revoke, competes on the axis where SMB buyers already reward vendors: fidelity and clarity over breadth.

Two consequences follow. First, the stealer threat increasingly lives inside the browser, through CDP enablement, debugger key capture and session riding past DBSC. Browser-process access monitoring (ST-07) will become the most important rule family, and it is also where a v3 driver delivers the most value per line of kernel code. That argues for scoping the eventual driver narrowly around handle protection for browsers and the agent rather than building a general-purpose kernel sensor. Second, because v1 cannot guarantee prevention, its credibility rests on honest incident semantics: "detected and contained, credentials probably exposed, here is the revocation checklist". A product built on that premise is both more truthful and more useful to employers than one that claims blocks it cannot enforce.
